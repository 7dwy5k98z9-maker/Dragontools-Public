Dragon Tools V9.8.2 - Build-Hinweise
=====================================

Diese Hinweise gelten für den aktuellen DragonTools-Quellstand unter Windows 10/11.

Voraussetzungen
---------------
- Python 3.12 oder 3.13
- Git für Klonen und Aktualisieren
- Python-Abhängigkeiten aus den mitgelieferten Requirements-Dateien

Installation für einen vollständigen Build
-------------------------------------------
1. Eine virtuelle Python-Umgebung anlegen und aktivieren.
2. Python und pip aktualisieren.
3. Folgenden Befehl ausführen:

   python -m pip install -r requirements-build.txt

Die Abhängigkeiten sind getrennt dokumentiert:
- requirements-runtime.txt: Programmstart
- requirements-optional.txt: optionale Bildanalyse
- requirements-test.txt: Tests
- requirements-build.txt: Windows-Build

Externe Medienprogramme
-----------------------
DragonTools bündelt Drittanbieterprogramme nicht im Git-Repository. Je nach verwendetem Arbeitsablauf werden FFmpeg/FFprobe, MKVToolNix, MediaInfo CLI, GPAC/MP4Box, dovi_tool, hdr10plus_tool, HandBrake, MakeMKV oder Rename My TV Series benötigt. Offizielle Downloadquellen und Zielpfade stehen in README.md beziehungsweise im öffentlichen Paket in TOOLS_INSTALLIEREN.txt.

Beim Start aus dem Quellcode können die Programme über die DragonTools-Einstellungen ausgewählt, über den Windows-PATH gefunden oder in der vorgesehenen third_party-Struktur abgelegt werden.

Build starten
-------------
Den Build aus einer Eingabeaufforderung im Projektordner starten:

   build_v9.bat

Das fertige Programm liegt anschließend unter:

   dist\DragonToolsV9.8.2\

Prüfung vor einer Veröffentlichung
----------------------------------
1. Gesamte Testsuite ausführen:

   python -m pytest -m "not dv_hdr_integration"

2. Release-Prüfung und Datenschutzprüfung ausführen.
3. Einen frischen Build erstellen und starten.
4. Den vollständigen Anwendungsordner als ZIP verpacken.
5. Eine SHA-256-Prüfsumme erzeugen.

Wichtige Sicherheitshinweise
----------------------------
- API-Schlüssel, lokale Einstellungen, Logs, Datenbanken und Medien gehören nicht in Git.
- build, dist, Caches und externe Programme bleiben außerhalb der Git-Historie.
- Die öffentliche Fassung verwendet ausschließlich Dragon Developer als Entwicklername.
- Bei einer fehlgeschlagenen Timestamp- oder Streamprüfung ersetzt oder verschiebt DragonTools die Quelldatei nicht.
